Overview

Brandle is a daily and unlimited Wordle-like game where you guess a mystery brand and receive color-coded feedback across five attributes: category, country of origin, founding year, revenue range, and employee count. The mechanic is tight; the content is surprisingly deep. Guess Apple — it's easier than you think. Guess Reckitt — it isn't.

The Problem

Brandle started as a class project: build something with a Supabase backend. I built a Wordle clone in a weekend and submitted it. But halfway through building it, I noticed something: the interesting version wasn't about words. It was about brands. Everyone has fuzzy mental models of companies — where they're from, how big they are, what they do — but those models are rarely tested. The guessing mechanic felt like a perfect fit for surfacing that uncertainty.

The question was whether it had legs beyond the classroom. A daily constraint-based guessing game based on brand attributes isn't an obvious hit. But Wordle proved the format works, and brands have a property that words don't: people have actual opinions about them.

Highlights

  • 01

    Multi-attribute feedback across five dimensions — green for exact, yellow for close, with higher/lower arrows on numeric fields. Five signals at once without feeling overwhelming.

  • 02

    Daily mode uses a deterministic seed so all players get the same brand each day. Unlimited mode picks randomly for replay. Both modes share stats, streaks, and a shareable result grid.

  • 03

    Difficulty modes with different guess limits and thresholds on numeric tolerance — the same brand can feel easy or brutal depending on how tight the proximity windows are.

  • 04

    Local stats and streak tracking with win rate, guess distribution, and current/best streak. A Supabase data model sits ready for leaderboards when auth is added.

  • 05

    Hard mode constraints force you to use revealed information in subsequent guesses — a meaningful constraint that changes how you reason through the remaining possibility space.

Under the Hood

The daily mode uses a deterministic seeding function — the same brand, same day, for every player, derived from the date. This means consistent results without needing to store a "today's puzzle" record in the database and no server-side state management for puzzle selection. Unlimited mode uses a pseudo-random picker that excludes the last 30 days of daily brands to avoid repetition.

The feedback algorithm evaluates five attributes simultaneously. Categorical and geographic fields are binary — exact or not. Three numeric fields (founding year, revenue, employee count) use graduated proximity feedback with higher/lower directional arrows. Tolerance thresholds are configurable per difficulty mode, which is what makes hard mode genuinely hard: the proximity windows tighten, so guesses that would score yellow in normal mode score gray.

"For content-driven games, curation is design work. Getting 200 brands with consistent, verifiable data across five attributes took longer than building the game itself."

Reflection

The most interesting design problem in Brandle wasn't the game mechanic — it was the dataset. Inconsistent founding year data (acquisition vs. original founding), revenue figures that lag by a year, subsidiary vs. parent company ambiguity — data quality directly determined game quality. I spent more time on data normalization than on React components.

The stats model was designed with future features in mind. Local state handles current and best streak; a Supabase table is populated on every completed game with a structure ready for a global leaderboard once authentication is wired up. Building the data model before the feature was the right call — retrofitting persistence is a pain.
