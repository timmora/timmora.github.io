Aporia

Solo Developer (in progress)

Overview

A personal finance app that takes the guesswork out of investing. Aporia builds customized portfolios based on what users actually care about — their goals, risk tolerance, and dealbreakers — and delivers smart, ongoing suggestions that evolve with them. Think Robinhood, but with a point of view.

What I built

End-to-end product in React and TypeScript — a 3-step onboarding questionnaire, an animated portfolio reveal, a live dashboard with real market data, and a suggestion engine that surfaces rebalancing and opportunity alerts.

Key features
  • Values-based onboarding: goals, risk profiling via behavioral scenarios, and ethical dealbreakers (fossil fuels, tobacco, weapons, etc.)
  • Custom portfolio generation across 12 curated ETFs, with dealbreaker-driven swaps (e.g. fossil fuel exclusion triggers solar ETF)
  • Live market data via Yahoo Finance API — real-time quotes, performance charts with SPY benchmark overlay, and 4 time ranges
  • Institutional intelligence panel surfacing Q4 2024 SEC 13F filings from Berkshire, ARK, and Vanguard mapped back to the user's holdings
  • Life event triggers (new job, baby, home, etc.) and an actionable suggestion inbox for rebalancing and milestone alerts
Tech stack
React 19 TypeScript Tailwind CSS Framer Motion Zustand React Query Recharts Express Yahoo Finance API Vite
Data & backend

Express API server proxies Yahoo Finance for live quotes and historical OHLC data, with in-memory caching (5-min TTL for quotes, 24-hr for long-range history). React Query handles stale data gracefully — users see last-known prices if the market data feed is unavailable. Portfolio state is managed in Zustand with no backend sync required in the current build.

Deployment

Monorepo with concurrent dev setup (Vite frontend + Node backend via pnpm). Built for deployment; production environment and hosting TBD.

What I'm proud of

The idea that your portfolio should reflect what you actually believe — and that enforcing that at the allocation level (not just as a filter) makes for a genuinely different product. The institutional 13F panel is also something I haven't seen in consumer investing tools, and it came together cleanly.

Ordo

Solo Developer

View live →
Overview

A full-stack productivity app built for students. Ordo uses Claude AI to decompose assignments into subtasks, generate daily briefings, and surface a ranked Daily Three — the three tasks that actually matter today — with a scheduling engine that respects your real daily capacity.

What I built

Full-stack web and mobile product — an 8-step onboarding wizard with AI syllabus parsing, a React dashboard with calendar, task, focus, and journal tabs, a FastAPI backend with 17+ endpoints, and a companion Expo app mirroring the core experience on iOS and Android.

Key features
  • AI task decomposition — Claude breaks any assignment into 3–7 timed subtasks, with a fast-path rule-based fallback for simple tasks
  • Constraint-based scheduler that maps subtasks into free slots respecting course blocks, calendar events, daily capacity limits, and preferred focus windows
  • AI daily briefing summarizing the day's priorities, focus stats, and a personalized tip — cached per user per day to minimize API calls
  • Syllabus PDF parsing during onboarding — Claude extracts course schedule and assignments directly from uploaded syllabi
  • Pomodoro-style focus timer with per-subtask time tracking, session logs, and streak counters
  • Encrypted journal with mood/energy tracking, three daily reflection prompts, and AI-generated weekly insights
  • Google Calendar OAuth sync and FullCalendar v6 with full RRULE recurrence support
Tech stack
React 19 TypeScript Tailwind CSS v4 shadcn/ui React Query Zustand FullCalendar dnd-kit FastAPI Claude API Supabase Clerk Expo Vite
Data & backend

Supabase (PostgreSQL) with RLS on every table — the frontend talks directly to the DB via the anon key, while FastAPI only steps in for AI, encryption, and OAuth. Auth uses Clerk with a custom token exchange endpoint that mints a Supabase session. Journal entries are AES-256 encrypted at rest with per-user keys and rotation support. Claude Sonnet 4.6 handles reasoning-heavy tasks; Haiku 4.5 handles syllabus parsing for cost. Prompt caching on system prompts reduces latency and spend across repeated calls.

Deployment

Frontend on Vercel with enforcing CSP headers; FastAPI backend on Render via Docker (Python 3.12-slim, dynamic port injection); database on Supabase; mobile on Expo with EAS Build. GitHub Actions CI runs RLS policy checks, TypeScript type checks, and backend ruff + pytest on every push.

What I'm proud of

The scheduling engine — building a free-slot map that actually respects how a student's day is structured (classes, capacity, focus windows) and greedily fitting the highest-priority work into it felt like solving a real problem, not just adding an AI wrapper. The multi-model strategy and prompt caching were also intentional choices I'm glad I made early.

Brandle

Developer & UI Designer — extended from a class project

View live →
Overview

A daily + unlimited Wordle-like game: guess a mystery brand and get color-coded feedback across category, country of origin, founding year, revenue range, and employee count.

What I built

The full React experience — guess flow, validation, win/lose states, shareable results, and stats — tuned to feel fast, polished, and replayable.

Key features
  • Multi-attribute feedback (green / yellow / gray) plus higher/lower hints on numeric fields
  • Daily puzzle (same answer per day) and Unlimited mode for replay
  • Difficulty modes with different thresholds and limits
  • Hints and hard-mode constraints
  • Local stats and streak tracking (win rate, distribution, streaks)
  • Auth + leaderboard-ready data model in Supabase
Tech stack
React 18 React Router Supabase Postgres JavaScript MUI / Emotion Bootstrap
Data & backend

Supabase hosts everything — no custom server. Brand rows come from a brands table; user results and stats can be written for persistence and leaderboards.

Deployment

Vercel, with SPA routing so routes like /game load correctly.

What I'm proud of

Turning a simple guessing mechanic into a real game loop: clear UX, meaningful feedback, and retention hooks — daily puzzle, streaks, stats, and unlimited play.

HoloOrbits

UX Lead

Overview

HoloOrbit is a browser-based multiplayer simulation where secondary school students collaborate in real time to solve orbital mechanics challenges. Built to make abstract science concepts click through play.

What I owned

As UX lead, I drove the redesign of the game's navigation, collaborative mechanics, and in-game feedback systems — turning a solo simulation into a genuinely engaging group experience for secondary school students.

Key outcomes
  • Redesigned the experience for real classroom use — shifted the game from single-player simulation to multiplayer, where students work together toward shared objectives
  • Replaced passive in-game prompts with a structured accuracy feedback system, giving students meaningful in-the-moment responses to their decisions
  • Ran a pilot test with college students, gathering structured feedback that validated the redesigned collaborative mechanics and drove a final round of UX improvements
Tech stack
Unity WebGL Figma
Team & timeline

Team of 4 across the Spring semester. I led UX and product direction; collaborated closely with a teammate on the accuracy feedback system and Unity/WebGL build.

What I'm proud of

Running a real pilot and watching students actually engage with the redesigned mechanics — not just complete the game, but debate decisions together. That shift from passive player to active collaborator was the whole design goal, and seeing it land made the semester worth it.
